# 2026-07-10

## HLK-RM58S WiFi module AT command timeout fix

**Problem**: Serial log showed `at+netmode=2` timing out after 2000ms. Module never responded to any AT command.

**Root cause**: `enter_at_mode()` pulled ES pin LOW for 1200ms then released it HIGH before sending any AT commands. The module exited AT mode, so all AT commands were treated as transparent data.

**Datasheet findings** (HLK-RM58S V1.30):
- ES (GPIO0) pin: pull LOW >50ms to enter AT command mode; keep LOW during entire AT session
- Pull LOW ≥8s for factory reset
- Release HIGH to exit AT mode
- Module boots in transparent mode by default
- AT security parameter uses `wpa2_aes` (not `wpa2_psk`)
- `+++` escape sequence does NOT work reliably on this module — ES pin is required

### Fix iteration 1 (+++ only — FAILED)
Tried using `+++` with 1100ms guard times, no ES pin. Module generated idle events during `+++` but never responded to `at\r\n` or `at+netmode=2`. Conclusion: `+++` is not reliable for HLK-RM58S; ES pin must be used.

### Fix iteration 2 (ES pin held LOW — CURRENT)
Per datasheet: ES pin must stay LOW throughout the entire AT command session.

**Files modified**:

1. **`hlk_rm58s.c` — `enter_at_mode()`**: Pull ES LOW, wait 1200ms, set AT_MODE state, verify with `at\r\n` → "OK"
2. **`hlk_rm58s.c` — new `exit_at_mode()`**: Release ES HIGH, 200ms delay
3. **`hlk_rm58s.c` — `commit_and_reboot()`**: Send `at+reconn=1` while ES still LOW, wait 500ms for TX, then `exit_at_mode()` before reboot
4. **`hlk_rm58s.c` — `hlk_rm58s_uart_rx_complete()`**: Added `hlk_uart_start_recv()` at end — HAL stops DMA RX in NORMAL mode after idle, must restart
5. **`hlk_rm58s.c` — `connect_sta()` security string**: Changed from `"wpa2_psk"` to `"wpa2_aes"` (module's native format)
6. **`hlk_rm58s_hal.c` — `HAL_UART_ErrorCallback()`**: Clear ORE/FE/NE/PE flags, restart DMA RX
7. **`hlk_rm58s.h`**: Added `hlk_rm58s_exit_at_mode()` declaration
8. **`task_wifi.c` — `get_security_type()`**: Added `"wpa2_aes"` → `HLK_SECURITY_WPA2_PSK` mapping

**Key facts**:
- ES pin is active-LOW for AT mode entry, must be held LOW during entire AT session
- `+++` escape does NOT work reliably on HLK-RM58S
- AT command security parameter is `wpa2_aes`, not `wpa2_psk`
- DMA RX must be manually restarted after each idle event (HAL NORMAL mode)
- UART error callback is needed to prevent permanent DMA RX lock-up on overrun
